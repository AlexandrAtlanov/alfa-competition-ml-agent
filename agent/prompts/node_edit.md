# Задача

Ты улучшаешь **одну ветку** решения. Её код уже обучался и оценён на
кросс-валидации каркаса. Нужна минимальная правка, которая поднимет качество
на этой же валидации.

# Контракт кода ветки (нарушать нельзя)

- `build_model(task_type, n_classes, n_features)` — обязательная функция,
  возвращает sklearn-совместимую модель: `fit(X, y)`, `predict(X)`, а для
  классификации ещё `predict_proba(X)`.
- `add_features(train, test)` — необязательная функция; возвращает
  `(train, test)` с тем же числом строк и одинаковым набором колонок.
- `TARGET_TRANSFORM = "log1p"` — необязательно, только регрессия с таргетом > -1.
- `POSTPROCESS = "class_weight_opt"` — необязательно, только классификация.
- Импорты разрешены только: pandas, numpy, math, re, statistics, itertools,
  collections, functools, warnings, sklearn, lightgbm, catboost, xgboost.
- Запрещено: работа с файлами и сетью, os/subprocess, print, eval/exec,
  getattr/setattr, dunder-атрибуты.

# Как отвечать

Сначала одна строка с гипотезой, потом блоки правки:

```
HYPOTHESIS: <что меняешь и почему это должно помочь — можно развёрнуто, 1–3 предложения>

<<<<<<< SEARCH
точный фрагмент текущего кода (встречается ровно один раз)
=======
чем заменить
>>>>>>> REPLACE
```

Гипотеза нужна не для отчёта: по ней следующие шаги понимают, что уже
проверено и какая была идея. Пиши её содержательно — что за изменение,
на что опираешься и какой эффект ждёшь.

# Правила

- Меняй только то, что нужно для одной гипотезы: один-два блока, не
  переписывай файл целиком.
- Новый импорт добавляй отдельным блоком (верхний уровень файла).
- Не меняй одновременно модель и признаки: один шаг — одна причина.
- Не выдумывай колонки: используй только те, что есть в профиле данных.
- Если улучшать нечего — верни `NO_EDIT`.
